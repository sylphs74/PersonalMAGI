# PersonalMAGI

Android（8GB RAM 以上の端末を想定）の MAGI風の合議AIアプリ。端末内の日本製LLMで動き、役割ごとにクラウドAI（Claude / ChatGPT / Gemini / Perplexity）も選べる。
中立の提案役が質問を「仮説」にまとめ、3体のLLMがその仮説を独立に審議（承認／否決＋対案）し、多数決で **可決 / 否決 / 保留** を出したうえで統合回答をまとめる。

## 構成

| 役割 | モデル | ライセンス |
|---|---|---|
| MELCHIOR（科学者） | Sarashina2.2 3B Instruct | MIT |
| BALTHASAR（母） | LLM-jp-3.1 1.8B Instruct4 | Apache-2.0 |
| CASPER（女） | Rakuten AI 2.0 mini Instruct（1.5B） | Apache-2.0 |
| 提案役（中立・仮説の作成のみ） | Gemma-2-Llama-Swallow 2B（1.6GB） | Gemma Terms of Use / Llama 3.3 License |

高性能モデル（メモリ10GB以上の端末向け、「モデル」タブで賢者ごとに自動／標準／高性能を選択）:

| 役割 | 高性能モデル  | ライセンス |
|---|---|---|
| MELCHIOR | Llama 3.1 Swallow 8B Instruct v0.5（4.7GB） | Llama 3.1 Community License |
| BALTHASAR | LLM-jp-3 7.2B Instruct3（4.2GB） | Apache-2.0 |
| CASPER | Rakuten AI 7B Instruct（4.2GB） | Apache-2.0 |

- 推論: llama.cpp（`b11982`）を NDK でネイティブ組み込み。量子化 GGUF を使用
- GPU: Adreno 7xx/8xx（Snapdragon 8 Gen 3 / 8s Gen 4 / 8 Elite など）では OpenCL で全層を GPU に載せる。使えない端末（Adreno 6xx など）では自動で CPU 実行。設定で切り替え可能。各賢者のパネルに実際の実行先（GPU/CPU）を表示
- メモリ: 8GB 端末に収めるため、モデルは **1体ずつ読み込み→審議→解放** を繰り返す
- 審議順: 提案役 → CASPER → BALTHASAR → MELCHIOR → 統合（MELCHIOR を載せたまま統合回答を書く）
- 審議は画面ではなくアプリ全体で動き、フォアグラウンドサービスと wake lock で裏に回しても・画面を消しても続く（通知に進行状況、裏にいる間に終われば結果を通知）
- 入力はテキスト（共有メニューからの文章・URL を含む）
- モデルは初回にアプリ内からダウンロード（Hugging Face、標準 約7.0GB）。ファイル名は実行時に HF API から解決
- ダウンロードは16MBずつの分割取得を複数接続で同時に行う（既定6本、設定で1〜8）。中断しても続きから再開し、バックグラウンドでも通知に進捗と速度を表示

## 任意のLLMの追加

- 端末内: モデル画面「＋ LLMを追加」から、Hugging Face の GGUF リポジトリ（量子化の優先順を指定してダウンロード）または端末内の .gguf ファイルを、役割（提案役・3賢者）を選んで追加できる。追加したモデルは役割のAI選択に並ぶ
- クラウド: 設定 → クラウドAI →「カスタムAPI」に OpenAI 互換 API の URL・キー（任意）・モデル名を入れると、Claude などと同じように役割に選べる（家庭内のサーバーへの http 接続も可）

## クラウドAIの選択

- 提案役・3賢者・審議結果のまとめ役ごとに「端末内／Claude／ChatGPT／Gemini／Perplexity」を選べる（モデル画面）。APIキーは設定画面で登録（各社の開発者向けAPI・従量課金。月額プランでは不可）
- キーは Android Keystore の鍵で暗号化して端末内に保存し、記録・ログには出さない
- モデル名は各社のモデル一覧APIから実行時に取得（Perplexity は Agent API の effort: fast / low / medium / high）
- 役割ごとのおすすめ（AIの特性 × 役割）:
  - 提案役: Perplexity（毎回Web検索・出典付きで、今日時点の事実に基づく仮説）
  - MELCHIOR: Gemini（幅広い知識と数学・科学の推論 → 論理・根拠・事実）
  - BALTHASAR: Claude（安全性と倫理を重視 → 人や社会への影響・守るべきもの）
  - CASPER: ChatGPT（自然で共感的な会話・暮らしの話題 → 気持ち・直感・実感）
  - まとめ役: Claude（意見を偏りなく整理し、事実を足さない）
- クラウドの賢者は端末内の賢者と並行して審議する。キー未登録・接続失敗のときは、その役割の端末内モデルが代理で審議する
- 審議結果の末尾にクラウドAIのトークン使用量を表示

## 仮説審議と Web 調査

- 提案役は3賢者とは別の中立モデル。細かい判断はせず、質問に対する「仮説」（暫定の答え）を1つ立てるだけ
- 小型モデルは自分の知識の古さ・誤りを判断できないため、翻訳・作文・計算などを除き、質問ごとに自動で Web を調べ（基本情報・最近の報道・一般検索）、その資料を仮説と一緒に3賢者へ渡す。日付・数値・出来事は資料に書かれたものだけを使うよう指示している
- 賢者が「判断材料不足」「確認が必要」などで判断できないときは、その賢者が自分で足りない事実の検索語を出し、アプリが調べた資料で審議し直す（1回まで）。集めた資料は後の賢者にも共有され、出典にも載る
- 仮説が「〜を調べる」のような行動・一般論になったときは仮説なしとし、3賢者が資料をもとに質問へ直接答える
- 結果画面は「審議結果」（仮説・決議・結論・出典）と「各賢者の判断」を別枠で表示
  - できるだけ一次情報に近いものを使う。個人ブログ・まとめ・知恵袋などは順位を下げ、公的機関・取引所・報道機関・証券会社を優先
  - 株価: Yahoo!ファイナンスのチャート API（日足6か月 → 直近終値・6か月の騰落率・高値安値・月末終値）。銘柄名からの証券コードは Wikipedia の上場情報で引く。株・銘柄の質問では、仮説に挙がった銘柄（最大3つ）を必ず株価と最近の報道で確認する
  - ニュース: Google ニュース RSS（報道機関・証券会社の記事を新しい順、半年以内を優先）
  - 天気: Open-Meteo（地名→座標→7日間予報。天気を尋ねる質問のときだけ）
  - 事典: 日本語 Wikipedia（検索→冒頭の要約）
  - 一般検索: DuckDuckGo lite（APIキー不要。非公式の HTML 版のため、仕様変更で結果が取れなくなることがある）
- 3賢者は仮説に対して「承認（補足）」または「否決（対案）」を出し、審議結果は結論・仮説・Web 資料の出典をまとめる
- 設定「提案役がWebで調べる」をオフにすると完全オフライン（送られるのは質問から作った検索語のみ。端末内の推論は従来どおり）

## 便利機能

- 共有から審議: 他のアプリで「共有 → PersonalMAGI」を選ぶと、その文章やURLが審議事項に入る。URLのページ本文は資料として読み込む（質問に直接URLを書いても同じ）
- 反論ラウンド（設定 → 審議）: 最初の判定のあと、各賢者が他の2人の意見を読んで1回だけ考え直す。考えを変えた賢者は「承認→否決（再考）」のように表示
- 出典番号と事実チェック: 資料に番号を振り、賢者と審議結果は根拠に [n] を付ける。審議結果の日付・数値が資料にない場合や、存在しない出典番号は「⚠」で表示
- クラウドAIの費用（設定 → クラウドAI）: トークン数×単価×為替で審議ごと・月ごとの概算を表示。月の上限を超えると、その月はクラウドの役割も端末内モデルで審議
- アプリの更新（設定 → 診断・このアプリについて）: GitHub Releases の新しい版を1日1回確認し、ダウンロードしてインストール画面を開く
- プリセット（モデル画面）: 速さ重視／精度重視／オフラインと、自分で保存した構成をワンタップで切り替え
- 審議記録: 検索、お気に入り（★は件数・期間の上限で消えない）、テキストで共有、長押しで複数選択して削除
- 定期審議（設定 → 定期審議）: 毎日／平日／週末の決まった時刻に自動で審議し、結果を通知して記録
- 分野別の一次情報: 法律の質問は e-Gov 法令API、ソフトウェアの版やリリースの質問は GitHub のリリース情報も調べる
- 端末の状態で自動切替（設定 → 端末内モデル）: 「自動」のとき、本体が熱い・電池温度が高い・充電せず残量30%未満なら標準モデルを使う

## APK の入手

[Releases](https://github.com/sylphs74/PersonalMAGI/releases) から `PersonalMAGI-0.1.<番号>.apk` をスマホでダウンロードしてインストールする（提供元不明のアプリのインストール許可が必要）。
以降はアプリの「設定 → 診断・このアプリについて → 更新を確認」から更新できる。

`main` に push すると GitHub Actions が APK をビルドして Releases に置く。

CI はビルド前に `scripts/check_models.py` で、`models.json` の全モデルが Hugging Face 上で解決できるかを確認する。

## 使い方

1. 「モデル」タブ →「必要なモデルをまとめてダウンロード」（既定は Wi-Fi のみ。提案役モデルも含む）
2. 「審議」タブで質問を入力
3. 「審議」を押す。各賢者のパネルをタップすると全文と速度（tok/s）が見られる

## 表示と記録の設定（設定タブ）

- 口調: 日本語（標準）/ エヴァ風（葛城風）/ 執事風 / メイド風 / 大阪弁（3賢者の回答と統合回答に適用）
- 設定画面の末尾にバージョン番号を表示

- 音楽: 「審議中に流す」（くり返し）と「審議完了で流す」（1回）をそれぞれ曲を選んで ON/OFF。中断・エラーでは流さない
- 設定の書き出し・読み込み: 設定と審議記録を JSON ファイルに保存・復元（記録は既存の記録に追加）。APIキーは書き出し時のパスワードで暗号化（PBKDF2-SHA256 + AES-GCM）して含められる。音楽・フォント・モデルは含まない
- 設定画面はメニュー形式（口調／表示／音楽／審議／端末内モデル／クラウドAI／審議記録／書き出し・読み込み／診断）
- カラースキーム: VS Code のカラーテーマを Open VSX から検索して取り込み、または .json（VS Code テーマ／アプリ形式）・.vsix を読み込み、色を1つずつ編集して自作も可能。書き出しにも含まれる
- テーマ: MAGI（標準）/ Tokyo Night / NERV（いずれもダーク）
- フォント: `.ttf` `.otf` `.ttc`、またはそれらを含む `.zip` を登録し、本文用と見出し・数値用を個別に選べる
- 審議記録: 記録のオン/オフ、件数上限（20〜300件/無制限）と保存期間（7〜365日/無期限）。記録画面から1件ずつ削除も可能

## 賢者ごとのモデル選択

- 「モデル」タブで賢者ごとに「自動／標準／高性能」を選べる
- 自動: 端末のメモリが条件を満たし、かつ高性能モデルがダウンロード済みなら高性能、それ以外は標準。機種変更しても端末に合わせて切り替わる
- 手動で選べばその選択に固定

## モデルの更新

- 確認は手動（「モデル」タブの「更新を確認」）と自動（起動時に週1回まで、Wi-Fi時のみ。設定でオフ可）
- 見つかるのは、同じファイルの差し替え・より良い量子化版・同じ系列で同じサイズの新世代（例: Sarashina2.2 3B → 2.3 3B、同じ配布元に限る）
- 更新するか見送るかは利用者が選ぶ。見送った版は再表示しない
- 「更新する」を選ぶと別の場所にダウンロードし、その間も今のモデルで審議に参加する。完了後に試しに読み込み、動けば切り替えて古いファイルを削除、動かなければ今のモデルを使い続ける
- 系列の判定は `models.json` の `family`（検索語・配布元・リポジトリ名の正規表現）で行う

## ローカルビルド

```sh
./scripts/fetch-llama.sh        # llama.cpp を app/src/main/cpp/llama.cpp に取得
./gradlew :app:assembleRelease  # NDK 29.0.13113456 / CMake 3.31.6 が必要
```

署名鍵はリポジトリに含めない。CI はリポジトリの Secrets（`SIGNING_KEYSTORE_BASE64`・`SIGNING_STORE_PASSWORD`・`SIGNING_KEY_ALIAS`・`SIGNING_KEY_PASSWORD`）から鍵を復元して署名する。
Secrets がない環境（フォークやローカル）では一時的なデバッグ鍵で署名されるため、上書き更新はできない。

- これは非公式のファン作品で、『新世紀エヴァンゲリオン』の権利者（株式会社カラー等）とは関係ありません。作中の「MAGI」を模した表現は個人の趣味によるものです
- モデルはアプリが実行時に Hugging Face の各配布元から取得し、それぞれのライセンス（上の表）に従います。モデルのファイルはこのリポジトリに含まれていません

- 脆弱性の報告は [SECURITY.md](SECURITY.md) を参照
- モデル差し替えは `app/src/main/assets/models.json` の `repo` と `quant`（優先順の量子化名）を書き換える
